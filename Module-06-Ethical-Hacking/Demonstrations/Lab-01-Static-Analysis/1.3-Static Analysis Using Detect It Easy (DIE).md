# Lab 1.3 — Static Analysis Using Detect It Easy (DIE)

## 🎯 Objective

Use Detect It Easy (DIE) to identify and examine important characteristics of a Windows executable during static malware analysis.

For this demonstration, the benign Windows executable `notepad.exe` is used as the analysis sample.

---

## 🧪 Requirements

- Windows analysis VM
- `notepad.exe`
- Detect It Easy (DIE)
- Isolated malware-analysis environment

---

## ⚠️ Safety

This demonstration uses the legitimate Windows `notepad.exe` executable.

When analyzing actual malware, always use an isolated virtual machine and take a clean snapshot before beginning the analysis.

---

## 🖥️ Sample Used

```text
notepad.exe
```

Default location:

```text
C:\Windows\System32\notepad.exe
```

Verify the file exists:

```powershell
Test-Path C:\Windows\System32\notepad.exe
```

Expected result:

```text
True
```

---

## Step 1 — Launch Detect It Easy

Open Detect It Easy (DIE) on the Windows analysis VM.

DIE is a static-analysis tool used to identify executable formats, architectures, compilers, packers, and other PE characteristics.

---

## Step 2 — Load the Sample

In DIE, open:

```text
C:\Windows\System32\notepad.exe
```

DIE will automatically analyze the executable.

---

## Step 3 — Examine the File Type

Check the information displayed by DIE.

Look for:

- File Type
- PE Format
- Architecture
- Compiler
- Linker

Record the values shown by your version of DIE:

```text
File Type: <observed value>
Architecture: <observed value>
Compiler/Linker: <observed value>
```

---

## Step 4 — Check for Packers or Protectors

Examine the Packer/Protector information.

DIE may identify whether an executable appears to use a known packer or protector.

Record the result:

```text
Packer/Protector: <observed value>
```

If none is detected, record:

```text
Packer/Protector: None detected
```

Detection results are indicators only and should be correlated with other analysis techniques.

---

## Step 5 — Examine PE Sections

Inspect the sections displayed by DIE.

Common PE sections include:

- `.text`
- `.rdata`
- `.data`
- `.pdata`
- `.reloc`

Record the sections actually displayed for `notepad.exe`.

Example:

```text
Sections:
<observed sections>
```

These sections help analysts understand how executable code and data are organized inside the PE file.

---

## Step 6 — Examine the Entry Point

Locate the Entry Point information displayed by DIE.

Record the value:

```text
Entry Point: <observed value>
```

The entry point indicates where execution begins when the executable is loaded.

---

## Step 7 — Examine Entropy

If DIE displays entropy information, examine the entropy values for the executable or its sections.

Record:

```text
Entropy: <observed value>
```

Higher entropy can sometimes indicate compressed or packed data, but entropy alone does not prove that a file is malicious or packed.

---

---

## 🔍 Understanding the Results

DIE provides an initial overview of an executable:

```text
Executable
     ↓
File Format
     ↓
Architecture
     ↓
Compiler / Linker
     ↓
Packer / Protector
     ↓
PE Sections
     ↓
Entry Point
     ↓
Further Analysis
```

This information helps determine what type of executable is being analyzed and whether additional investigation is required.
