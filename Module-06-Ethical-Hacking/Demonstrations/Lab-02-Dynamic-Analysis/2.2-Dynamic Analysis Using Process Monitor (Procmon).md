# Lab 2.2 — Dynamic Analysis Using Process Monitor

## 🎯 Objective

Use Process Monitor (Procmon) to monitor file system, registry, process, and thread activity generated by a running Windows process.

For this demonstration, the benign Windows executable `notepad.exe` is used as the analysis sample.

---

## 🧪 Requirements

- Windows analysis VM
- `notepad.exe`
- Process Monitor (Procmon)
- Isolated malware-analysis environment

---

## ⚠️ Safety

This demonstration uses the legitimate Windows `notepad.exe` executable.

When analyzing actual malware, always use an isolated virtual machine and take a clean snapshot before beginning the analysis.

---

## 🖥️ Sample Used

```text
notepad.exe
```

Default location:

```text
C:\Windows\System32\notepad.exe
```

Verify the file exists:

```powershell
Test-Path C:\Windows\System32\notepad.exe
```

Expected result:

```text
True
```

---

## Step 1 — Launch Process Monitor

Open Process Monitor (Procmon) on the Windows analysis VM.

If prompted to allow Process Monitor to capture system activity, allow it.

Procmon monitors real-time system activity including:

- File System
- Registry
- Process Activity
- Thread Activity
- Network Activity

---

## Step 2 — Clear Existing Events

Before starting the demonstration, clear the existing captured events.

Use:

```text
Edit → Clear Display
```

or press:

```text
Ctrl + X
```

This makes it easier to identify activity generated during the demonstration.

---

## Step 3 — Start the Sample

Launch:

```text
C:\Windows\System32\notepad.exe
```

You can also start it from PowerShell:

```powershell
Start-Process C:\Windows\System32\notepad.exe
```

Keep Notepad running.

---

## Step 4 — Locate the Process

Return to Process Monitor.

Use the filtering functionality:

```text
Filter → Filter...
```

Create a filter for:

```text
Process Name
is
notepad.exe
```

Select:

```text
Include
```

Apply the filter.

Procmon will now primarily display events associated with `notepad.exe`.

---

## Step 5 — Examine File System Activity

Observe events related to file-system operations.

Look for operations such as:

- `CreateFile`
- `ReadFile`
- `WriteFile`
- `QueryInformationFile`
- `CloseFile`

Examine fields such as:

- Process Name
- PID
- Operation
- Path
- Result
- Detail

Record interesting observations:

```text
Process: notepad.exe
Operation: <observed operation>
Path: <observed path>
Result: <observed result>
```

---

## Step 6 — Examine Registry Activity

Observe registry-related operations generated by the process.

Common operations include:

- `RegOpenKey`
- `RegQueryValue`
- `RegSetValue`
- `RegCloseKey`

Record any relevant registry activity actually observed:

```text
Operation: <observed operation>
Path: <observed registry path>
Result: <observed result>
```

Do not assume that every registry operation indicates suspicious behavior.

---

## Step 7 — Examine Process Activity

Observe process-related events generated while Notepad is running.

Look for operations such as:

- Process Create
- Process Exit
- Thread Create
- Thread Exit

Record any relevant events:

```text
Process: notepad.exe
Operation: <observed operation>
Result: <observed result>
```

---

## Step 8 — Examine Event Details

Select an interesting event in Procmon.

The lower pane provides additional information about the selected event.

Examine:

- Event Properties
- Stack
- Process Information
- Command Line
- User
- Integrity

Record useful observations from the event details.

---

## Step 9 — Observe Application Activity

Perform a simple action in Notepad, such as:

- Type some text

Then save the file inside the isolated VM if required for the demonstration.

Observe the new Procmon events generated by the activity.

Look for file operations related to the file you interacted with.

Create a summary of the Procmon analysis:

---

## 🔍 Understanding the Results

Process Monitor allows analysts to observe what a process does while it is running:

```text
Running Process
      ↓
Process Monitor
      ↓
File Activity
      ↓
Registry Activity
      ↓
Process / Thread Activity
      ↓
Runtime Behavior
```

This makes Procmon useful for identifying changes and operations that cannot be determined from static analysis alone.
