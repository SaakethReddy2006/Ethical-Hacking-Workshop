# Lab 2.4 — Dynamic Analysis Using DNSQuerySniffer

## 🎯 Objective

Use DNSQuerySniffer to monitor and analyze DNS queries generated by applications running on a Windows system.

For this demonstration, the benign Windows executable `notepad.exe` is used as the analysis reference.

---

## 🧪 Requirements

- Windows analysis VM
- `notepad.exe`
- DNSQuerySniffer
- Isolated malware-analysis environment

---

## ⚠️ Safety

This demonstration uses the legitimate Windows `notepad.exe` executable.

When analyzing actual malware, always use an isolated virtual machine and take a clean snapshot before beginning the analysis.

---

## 🖥️ Sample Used

```text
notepad.exe
```

Default location:

```text
C:\Windows\System32\notepad.exe
```

Verify the file exists:

```powershell
Test-Path C:\Windows\System32\notepad.exe
```

Expected result:

```text
True
```

---

## Step 1 — Launch DNSQuerySniffer

Open DNSQuerySniffer on the Windows analysis VM.

DNSQuerySniffer captures DNS queries sent by applications and displays information about the DNS communication.

It can display information such as:

- Process ID
- Process Name
- Query Name
- Query Type
- Response
- Response Code

---

## Step 2 — Select the Network Interface

If DNSQuerySniffer asks you to select a network interface, choose the interface currently being used by the Windows analysis VM.

For example:

- Ethernet
- Wi-Fi
- VMware Network Adapter

Select the appropriate interface and begin capturing DNS queries.

---

## Step 3 — Start the Sample

Launch:

```text
C:\Windows\System32\notepad.exe
```

You can also start it from PowerShell:

```powershell
Start-Process C:\Windows\System32\notepad.exe
```

Keep Notepad running during the observation.

---

## Step 4 — Observe DNS Queries

Monitor the DNSQuerySniffer window for DNS requests.

Look for fields such as:

- Process Name
- Process ID
- Query Name
- Query Type
- Response
- Response Code

Record any DNS queries actually observed.

Example:

```text
Process: <observed process>
PID: <observed PID>
Query: <observed domain>
Query Type: <observed type>
Response: <observed response>
```

---

## Step 5 — Check the Sample Process

Search the captured entries for:

```text
notepad.exe
```

If DNSQuerySniffer does not show any DNS queries generated by `notepad.exe`, record:

```text
No DNS query generated by notepad.exe was observed during the demonstration.
```

This is a valid observation.

A process not generating DNS traffic does not indicate a problem; applications only generate DNS queries when they need to resolve domain names.

---

## Step 6 — Examine Query Types

Examine the Query Type field.

Common DNS query types include:

- `A`
- `AAAA`
- `CNAME`
- `MX`
- `TXT`

Record the query types actually observed during the demonstration.

---

## Step 7 — Examine Responses

If a DNS response is captured, examine:

- Response
- Response Code

Common response codes include:

- `NOERROR`
- `NXDOMAIN`

Record the information displayed by DNSQuerySniffer.

---

## Step 8 — Record Observations

Create a summary of the DNS analysis:

| Property | Observation |
|---|---|
| Process | \<observed process\> |
| PID | \<observed PID\> |
| Query Name | \<observed domain\> |
| Query Type | \<observed type\> |
| Response | \<observed response\> |
| Response Code | \<observed code\> |

Only document DNS activity actually observed during the demonstration.

---

## 🔍 Understanding the Results

DNSQuerySniffer helps analysts correlate DNS activity with running processes:

```text
Running Process
      ↓
DNS Request
      ↓
DNSQuerySniffer
      ↓
Query Name
      ↓
DNS Response
      ↓
Network Behavior Analysis
```

During malware analysis, DNS activity can provide useful clues about applications attempting to communicate with external domains.

However, a DNS query by itself does not prove that an application is malicious.
